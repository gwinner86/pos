⚙️ Automation/Trigger Consideration
To ensure data accuracy, you should consider using database triggers or application logic when a sale is completed:

Inventory Reduction: When a sale is marked 'Completed', the application must reduce the Quantity in the Inventory table for the corresponding ProductVariantId and LocationId.

Cost Capture: Before saving the SaleItem, the application must query the Cost table to find the current Cost for that ProductVariantId and copy it into the CostAtSale field. This ensures profit reports are accurate even if the cost changes tomorrow.

Multi-Tenancy Core: Tenant, Company, Location

Operational Data: Inventory, Pricing, Cost

Default Account creation Process
------------------------------------------------


When a new company (Company A) registers, the system should execute the following steps in sequence:

Step 1: Create the Tenant and Company Records
The API registers the top-level account and the company under it.

Create Tenant Record: (e.g., ID T-001)

Create Company Record: (e.g., ID C-A) with a Foreign Key to T-001.

Create Default Location: Create at least one default location (e.g., 'Main Store' or 'Headquarters') linked to C-A.

Step 2: Create the Default Admin User
The new company needs a user who can log in immediately to set up the rest of the organization. This user is often the person who initially signed up.

Create Role Record (If missing): Ensure a base role like 'Company Admin' (e.g., RoleID: 2) exists in your global Role table.

Create User Record:

Create a new user entry (e.g., ID U-Admin) in the global User table.

This user will use the initial login email and password provided during sign-up.

Step 3: Link the User to the Company (The Crucial Step)
This step grants the new user access to the newly created company with the highest administrative role.

Create UserCompanyAssignment Record:

UserId = U-Admin

CompanyId = C-A

RoleId = 2 (Company Admin)

LocationId = NULL (since they have company-wide access)



NB 

Action,Why it's Best Practice
Do NOT require the company to create the first user manually.,This leads to a complex initial setup and a window where the company exists but cannot be accessed.
DO create the default admin user automatically.,"Provides an immediate, functional entry point. The system should provision a User record and an Assignment record simultaneously."
DO use the UserCompanyAssignment table for this link.,"This ensures the user's login is centralized (in the User table) but their access rights are securely tied to the new Company record, adhering to the multi-tenant design."

 LANGUAGE sql
AS $function$

   select f.feeid as chargeid, f.collectionorpayout as drpayoutcrcollection,f.lowerlimit, f.upperlimit, f.paypartnerflatamount as paypartnerflatfeeamt, f.paypartnerrate as paypartnerfeerate,
  f.eganowflatamount as eganowflatfeeamt, f.eganowrate as eganowfeerate, f.cappedat as totalfeemustnotexceedamt
